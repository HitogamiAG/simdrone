# Площадка для дрона

Статическая площадка **2,5×2,5×0,3 м**, в центре верхней поверхности —
ArUco **0,5×0,5 м**, словарь `DICT_4X4_50`, ID `0`, чёрная рамка в одну ячейку.
Все размеры в метрах (уточнены пользователем). Исходник создан в Blender 5.2.2 LTS.

## Подключение к миру Gazebo

Добавить внутрь `<world>` нужного файла в `worlds/`:

```xml
<include>
  <uri>model://drone_pad</uri>
  <name>landing_pad_01</name>
  <pose>0 0 0 0 0 0</pose>
</include>
```

`pose` — XYZ в метрах и roll/pitch/yaw в радианах. Начало координат — центр
нижней грани; при Z=0 низ стоит на земле, верх коллизии находится на Z=0,3.
Для нескольких площадок использовать разные `<name>` и позиции.
Корневая `models/` уже входит в `GZ_SIM_RESOURCE_PATH` Docker-поставки;
для включения новых ресурсов в образ пересобрать `gazebo-service`.

Визуал площадки и коллизия — одинаковые аналитические box в SDF.
Маркер — белая plane и чёрные plane-ячейки; внешние textures/meshes и
сетевые загрузки Gazebo не нужны. Его planes не создают дополнительных коллизий.
Белое поле вокруг маркера имеет ширину 1 ячейка (0,083333 м), полный белый квадрат
0,666667×0,666667 м. Размер **0,5 м** относится к маркеру вместе с чёрной рамкой,
без белого поля; это `markerLength` для оценки позы OpenCV.

Белый фон поднят над верхом на 0,1 мм, чёрные ячейки — на 0,2 мм, чтобы избежать
z-fighting. Верхний край немодифицированного рисунка направлен в локальный +Y,
правый — +X. Вращение экземпляра мира вращает и маркер.

## Файлы и повторная генерация

- `drone_pad.blend` — исходная сцена, геометрия и материалы, применённый scale.
- `drone_pad.glb` — браузерная модель с материалами, без внешних ресурсов.
- `model.sdf`, `model.config` — готовая модель Gazebo.
- `aruco_4x4_50_id0.png` — 800×800, включает белое поле; маркер занимает 600×600.
- `manifest.json` — размеры, система координат, описание маркера, хеши ресурсов.
- `export.py` — генератор исходника и всех экспортов, без зависимости Blender от OpenCV.

Из корня проекта:

```sh
~/Downloads/blender-5.2.2-linux-x64/blender --background --factory-startup \
  --python-exit-code 1 --python models/drone_pad/export.py
docker run --rm --entrypoint gz -v "$PWD/models:/models:ro" \
  uav-gazebo-service:local sdf -k /models/drone_pad/model.sdf
```

Генератор создаёт пакет заново из параметров и битовой матрицы в `export.py`;
ручные изменения `.blend` при генерации не сохраняются. Битовая матрица получена
через OpenCV 4.12.0 `generateImageMarker(DICT_4X4_50, 0, 6, borderBits=1)`.
[Описание генерации и детекции ArUco в OpenCV](https://docs.opencv.org/4.10.0/d5/dae/tutorial_aruco_detection.html).
GLB использует Y вверх; поворот корня +90° вокруг X возвращает Gazebo Z вверх
(матрица `glb_to_gazebo` в manifest).

Добавление площадки в мир меняет его статическую геометрию: для карты frontend
нужно также обновить GLB и manifest соответствующего пакета участка. Этот пакет
поставляет отдельную модель; `worlds/empty.sdf` пока её не включает.

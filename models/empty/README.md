# Пакет мира empty

`simdrone-empty` 1.1.0, Blender 5.2.2 LTS. Плоскость 200×200 м,
центр (0, 0, 0), поверхность Z=0; в мире две площадки спауна.

- `empty.blend` — исходник мира, ground_plane, sun и две площадки с ArUco.
- `world.glb` — статическая геометрия участка и обеих площадок со встроенными материалами.
- `../../worlds/empty.sdf` — визуальная и collision plane, площадки, свет, physics и плагины
  единственного описания `worlds/empty.sdf`.
- `manifest.json` — identity, bounds, матрицы осей, точки площадок и поверхности,
  версия Blender, SHA-256 файлов.
- `export.py` — повторный экспорт; настройки читаются из `worlds/empty.sdf` и сохраняются в свойствах сцены.
- `verify.py` — хеши, структура исходника и обратный импорт GLB.

Gazebo: XYZ, Z вверх, метры. GLB: `(x, y, z) = (X, Z, -Y)`.
В Three.js с Z вверх применить к корню GLB поворот +90° вокруг X
(`glb_to_gazebo`). Дроны используют Gazebo XYZ напрямую. Матрицы manifest
записаны строками; для Matrix4.set передавать элементы в порядке строк.
Bounds имеют нулевую высоту: это поверхность, не объём полёта.

Collision plane Gazebo бесконечна, как в исходном empty; визуальная площадка
ограничена ±100 м. Bounds не ограничивают полёт. SDF задаёт аналитическую
плоскость по размерам mesh Blender; отдельный collision mesh и текстуры не нужны.
Свет и фон GLB не содержит: браузер задаёт освещение отдельно.

Площадки `landing_pad_01` и `landing_pad_02` включены на `(-3,0,0)` и `(3,0,0)`.
Их локальный `spawn_pad__<id>` frame задаёт начало координат `x500_gimbal`:
Z=0,292 м, центр площадки под дроном, yaw берётся из SDF. Высота выведена из нижней
границы коллизии шасси и зазора 5 мм. Backend закрепляет выбранный ID за дроном.

## Экспорт и проверки

Из корня проекта:

```sh
~/Downloads/blender-5.2.2-linux-x64/blender --background models/empty/empty.blend --python models/empty/export.py
~/Downloads/blender-5.2.2-linux-x64/blender --background models/empty/empty.blend --python models/empty/verify.py
docker run --rm --entrypoint gz -v "$PWD/worlds:/worlds:ro" uav-gazebo-service:local sdf -k /worlds/empty.sdf
```

Редактировать исходник, затем экспортировать. Поддерживается центрированная
горизонтальная прямоугольная плоскость Z=0; сложная геометрия требует расширения
экспортёра. При смене поставки обновить свойство сцены `package_version`.
Резервные `.blend1` не входят в поставку. Генерация через MCP использует отдельную
сцену и сохраняет ранее открытые сцены; повторный background экспорт сохраняет
обычный .blend с единственной сценой empty. Экспорт импортирует исходную Blender
модель `models/drone_pad/drone_pad.blend` и размещает две копии по координатам
из списка `configured_pads` в скрипте.

Compose уже монтирует manifest в Backend. GLB пока не подключён к сборке frontend.
Экспорт обновляет `worlds/empty.sdf`; изменения попадают в Gazebo после пересборки образа и обновления контейнера. Геометрия соответствует текущему empty. Шаблон настроек читается из этого же SDF; сохранённая копия в Blender не переопределяет настройки мира.

## Результат 05.10.2026

Исходник повторно открыт Blender background, GLB импортирован обратно:
максимальная ошибка координат четырёх углов **0 м**, transforms, единицы и хеши
проверены. `gz sdf -k` в Docker: `Valid`, с унаследованным предупреждением
о `magnetic_field` внутри `physics` (элемент не описан схемой SDF).

Изолированный реальный `gz sim -s -r --headless-rendering` загрузил empty,
ground_plane 200×200 и sun, ответил `/world/empty/scene/info`.
После унификации каталогов образ пересобран: оба плагина
`simdrone-navsat-system` и `simdrone-magnetometer-system` загружены реальным
процессом Gazebo (проверено через `/proc/<pid>/maps`). Контрактные проверки,
regression и smoke прошли с миром из `/opt/uav/worlds/empty.sdf`.
Проверка пространственного совпадения в браузере, контакт/посадка в браузерном
сценарии и направление маркеров остаются открытыми. Пакет экспортирован;
полная браузерная интеграционная приёмка остаётся открытой.

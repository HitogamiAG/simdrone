# Flight API: реализация и проверка

## Статус

Flight API реализован в Backend и PX4 Hub. React-карта и интерфейс джойстика остаются следующим этапом. Backend хранит определения миссий в SQLite; Hub владеет исполнением через MAVSDK. Один PX4 instance выполняет одну миссию или одну Offboard-сессию.

## Контракт

Публичные маршруты и ограничения описаны в [README Backend](../backend/README.md#api). Внутренние маршруты Hub и flight state machine описаны в [README PX4 Hub](../px4-hub/README.md#api). Миссии используют точки XYZ Gazebo в метрах и сохраняют имя мира вместе со снимком `spherical_coordinates`. Перед каждым запуском Hub сверяет контекст с Gazebo. Загрузка миссии, RTL, посадка и возврат подтверждаются полётным состоянием, а не ответом о принятии команды.

Сохранение миссий переживает перезапуск Backend через Compose volume `backend-missions`. Активные выполнения и публичный реестр Backend остаются in-memory. При сбросе runtime поколения не восстанавливаются, активные операции прерываются через Hub lifecycle.

Offboard-команды передаются WebSocket-сессии с одноразово возвращаемым token и возрастающим `seq`. Hub держит только последний ввод. После 0,5 с без свежей команды задаёт нулевые скорости, после 5 с запускает RTL. Пределы — до 3 м/с горизонтально, до 1 м/с вертикально, до 60°/с yaw.

## Проверка

Контрактные тесты Backend и Hub покрывают сохранение/ревизии, преобразование координат, конфликт режимов, владение сессией, проверку token/seq, потерю ввода и проверки lifecycle. Backend: 18 тестов; Hub: 32 теста. Они выполнялись в Docker с тестовыми адаптерами и не заменяют настоящую симуляцию.

Сквозная проверка полётов в этой поставке ещё не выполнена. Её следует выполнить последовательно в Docker: ручной взлёт и движение по осям; RTL после отключения управляющего клиента; Mission через несколько точек; отмена маршрута; наблюдаемые посадка и disarm; pause/resume и reset при активной операции. Полный Compose стек недоступен в текущем checkout: игнорируемые ресурсы `third-party`, требуемые Gazebo Service, отсутствуют. Mock-тесты не трактуются как проверка реального PX4/Gazebo.

## Ограничения MVP

Симуляционный возврат использует RTL PX4 и не гарантирует точную посадку на метку. Маршруты не обходят препятствия и не включают остановки, камеру или действия в waypoint. Запуск и история выполнения не сохраняются между перезапусками Backend/Hub. Нужны активная сферическая привязка мира и совпадение PX4 home со станцией. React UI, авторизация пользователей, TURN и multi-worker Backend не входят в этот этап.
